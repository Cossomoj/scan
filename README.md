# Лист — подпись PDF

Сервис визуального подписания PDF. Можно подписать файл в браузере или создать отдельные ссылки для последовательного подписания несколькими людьми.

## Возможности и ограничения

- Самостоятельное подписание выполняется в браузере, без отправки документа на сервер.
- Подпись можно нарисовать или загрузить из PNG, JPG либо SVG размером до 5 МБ.
- При запросе другим участникам PDF хранится на сервере до семи дней. Участникам и владельцу выдаются отдельные случайные ссылки; сохраните их при создании — повторно получить их нельзя.
- Ссылки являются секретом: любой обладатель ссылки подписанта может открыть документ и подписать его. Входа в аккаунт, проверки личности и уведомлений по электронной почте нет.
- Подпись является изображением, добавленным в PDF. Это не криптографическая или квалифицированная электронная подпись; проверки подлинности и защищённого журнала аудита нет.
- Размер файла до 20 МБ, до 100 страниц. Защищённые паролем, повёрнутые и обрезанные страницы не поддерживаются.

## Локальный запуск

Требуются Node.js 24 и pnpm 11. Выполните pnpm install, pnpm build, pnpm start и откройте http://localhost:3000. Проверка: pnpm test.

## Развёртывание

Команда docker compose up -d --build запускает приложение и Caddy. Caddy получает сертификат для домена из Caddyfile; порты 80 и 443 должны быть доступны извне. Данные SQLite сохраняются в Docker volume sign_data.

GitHub Actions запускает тесты и сборку. На ветке main после успешной проверки он передаёт архив текущего коммита по SSH ограниченному серверному ключу; необходимы секреты окружения production: DEPLOY_SSH_KEY и DEPLOY_KNOWN_HOSTS. На сервере команда ключа должна безопасно развернуть архив и выполнить docker compose up -d --build.
