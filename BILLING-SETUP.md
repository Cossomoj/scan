# Подготовка ЮKassa и чеков

Платный режим и реальные платежи отключены. Сохранение реквизитов в админке не включает их. Рабочие платежи намеренно не реализованы до согласования и реализации порядка фискализации пополнений, списаний и возвратов.

В разделе «Настройки» админки можно сохранить идентификатор магазина и секретный ключ ЮKassa. Ключ шифруется; файл `payment-settings-key` в постоянном каталоге `DATA_DIR` нужно резервировать вместе с базой. Старые настройки CloudPayments не используются и остаются в отдельной таблице. Не передавайте ключ в переписке и не публикуйте его в репозитории.

Для проверки используйте отдельную базу и тестовый магазин с ключом `test_…`. `BILLING_ENABLED=1` предназначен только для изолированного тестирования: в рабочей конфигурации сайта его включать нельзя. Тестовые платежи не меняют настоящий баланс и тарифы. Сервер сверяет состояние платежа непосредственно с API ЮKassa, проверяя магазин, идентификаторы, сумму, валюту и тестовый режим.

В настройках уведомлений тестового магазина укажите `https://конторка.рф/api/yookassa/webhook` и события `payment.succeeded`, `payment.canceled`, `refund.succeeded`. Адрес должен быть доступен по HTTPS. После возврата из ЮKassa статус дополнительно проверяется через API.

В кабинете ЮKassa необходимо настроить «Чеки от ЮKassa» и налоговый режим ИП: АУСН 8%, без НДС. Тестовый запрос содержит признак «без НДС» (`vat_code: 1`) и полную предоплату; это технический пример, а не утверждённая схема работы с балансом. Необходимо уточнить у бухгалтера и ЮKassa порядок чеков при пополнении от 50 ₽, последующем списании за документы, приобретении тарифа и возвратах. После согласования нужно реализовать связанные чеки, повторные запросы и сверку операций, проверить их в тестовом магазине и только затем отдельно доработать и проверить включение реальных платежей.

При подключении платного режима исходный PDF и изменения временно передаются на сервер для сборки результата. Файл обрабатывается в памяти и новым механизмом на диск не записывается.
